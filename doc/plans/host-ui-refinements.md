# Host toolbar and Preferences refinements

Implemented above PR37 on `feat/host-ui-refinements`. The original worktrees and published branches are preserved. This is a host UI/settings change; the matching host/viewer protocol remains **14**. No viewer, installer or packaging build was performed here.

## Completed

- The docked toolbar contains character selection, Login, Chat, monitors, Preferences, Expanded/Condensed and a panel docking toggle. The permanent Characters, View and Next buttons are hidden. Login opens the next available profile; its context menu selects a profile. Character cards/selection retain concise settings, workspace, monitor, restart/cancel and logout actions.
- Quick actions share the docked toolbar row with a small divider. Detached controls allow a second quick-action row. Labels collapse from the end of the ordered list before actions enter an overflow menu. Buttons retain tooltips and overflow preserves order and the captured management target.
- Attention is a default, removable quick action. Its compact label is the eligible attention-item count, not an icon. Click toggles the inbox; right-click opens navigation/filter options. The count represents eligible conversations/offers, rather than summing every unread message. Migration adds Attention once to older configurations when capacity permits, without removing user actions. Removing it in the new UI remains respected after restart; a full 12-action configuration is preserved.
- Chat is a toggle button with selected-state feedback. Chat and character panels have dock/pop-out buttons; detached panels retain Always on top controls. The monitor dropdown checks open monitors and closes them when toggled off. Existing monitor chat, exchange, rate/budget, ownership/restriction and capture behavior remain intact.
- Expanded/Condensed works in detached character controls too. The arrow adjusts the panel height and shows/hides cards/details; quick actions remain available. These modes use the existing saved control-density choice. Advanced Minimal is retained in Preferences, with reveal/tray/recovery routes.
- Preferences has sidebar categories with top tabs: Layout & theme (Layout/Appearance); Character settings (Profile/Sounds/Viewer settings/Session); Chats & notifications (Conversations/Attention/Reading); Audio & voice; Switching & monitors; Controls (Quick actions/Keyboard shortcuts); Advanced (Diagnostics/Files & recovery).
- Character tabs share a fixed profile selector. Saved slot names/modes/order/Attention inclusion and live account alias/color/sounds retain their distinct ownership. Offline account controls explain their disabled state. Global Chat filters/reading and audio policies remain separate from account sounds. No chat content or account contents are added to preferences.
- Pages use short introductions only where useful, including Quick actions, and hover tooltips for detail/ranges. Quick actions have an ordered text/icon preview. Colors show their swatch; imported WAV display filenames persist without adopting source paths. Delay/animation settings enable only when applicable.
- OK accepts and closes, Apply accepts/saves without closing, and Cancel discards changes since the last accepted application. Switching character tabs retains independent drafts. WAV assets are written after validation; Cancel never writes a new asset. Repeated Apply updates label/mode/modifier baselines. Successful retry feedback distinguishes accepted choices from a newer draft.
- Copying is an explicit action, not a deferred checkbox. Copy/lifecycle actions capture the selected slot and identity before leaving Preferences, offer save/discard/Cancel when there is an unaccepted draft, and recheck ownership before execution. The existing bounded copy/restart/native logout flows remain authoritative.
- Numeric validation gives the actual range, navigates to the offending tab and reveals its field. Conflicting shortcuts/actions identify the affected row. Navigation, the profile selector, introductions and footer remain fixed while the field viewport scrolls.
- Scrolling lays controls out from absolute model coordinates, suppresses copied pixels during movement, and redraws the affected viewport/children. The fields container erases its own bounds; the dialog clips child controls. Standalone scrollbars use theme-matching painting and captured thumb/arrow/page/wheel handling, with native High Contrast behavior retained. Literal ampersands display correctly.

## Saved choices

The existing `%LOCALAPPDATA%\FolderstormSessions\Prototype-v1` root and FHP1 transaction/backup remain. FSX2 reads FSX1 experience data and records one-time toolbar migration. FSC4 reads FSC2/FSC3 chat data and adds a bounded display filename for custom sounds. Existing options, colors, names, masks, shortcuts, pins and profile folders remain. Older hosts do not understand the new component formats; downgrade compatibility is not claimed. Protocol 14 is unchanged because no IPC messages or viewer commands changed.

Preferences remains owned by the stable main host and positions near the panel that invoked it, so docking a panel during Apply does not give Preferences a hidden owner. The last visited page is remembered for this host session; each category remembers its tab while the dialog is open.

## PR37/38 review follow-up

The reported account-draft, alias-label and density-arrow findings were confirmed in the published source. Preferences now compares account drafts with their accepted originals before checking account ownership or inserting bounded records. Only edited appearance/sound components are written. Untouched disconnected or replaced accounts cannot block global changes, and a full appearance/sound store does not acquire unchanged default records. Edited accounts still require the captured login identity. Each Apply refreshes the baselines so another Apply after a disconnection does not replay earlier account edits.

Changing an alias updates an unchanged automatically seeded profile label (native name or previous alias), including clearing the alias back to the native name. Custom labels, labels edited in the same draft and labels changed by a newer login are preserved. Applied labels refresh in Preferences as well as the host. Existing WAVs load into the selected draft only on Preview; importing still validates immediately, and Apply/Cancel asset rules remain intact. The density arrow now advertises the same saved-state action as its handler; automatic compaction is explained in its tooltip and still yields when more window space becomes available.

The affected `preferences` regression was extended and rerun with the same strict C++17 flags. It covers full stores, untouched/edited accounts after ownership loss, selective record insertion, rejection without partial writes, imported/renamed sound drafts, repeated accepted baselines, alias/default/custom labels and preserving unedited appearance fields. `git diff --check` passed. Windows acceptance should additionally check a theme-only Apply after an unrelated logout; alias Apply twice/clear/custom label; Preview/import/reset then Cancel; and the arrow while automatically compacted and after enlarging docked/detached controls. No new native build was run.
