# Persistent host Preferences and expanded profile copying

Implemented on `feat/host-preferences`, isolated worktree `/workspace/Folderstorm-host-preferences`, above unmerged PR34 head `c1ccc4779363cef1c10a6c09186d268432e722d0`. Existing checkouts, private profile directories and published history remain intact. Protocol **14** distinguishes the expanded startup copy policy; build the matching host and viewer together. Native Windows acceptance remains pending.

## Completed

- Accepted Host Preferences save immediately. Quick menu changes, pins, panel placement, background modes, docking and character labels save automatically after a short debounce; moving a panel does not write on every mouse movement. Save failures retain the prior file, remain visible in the host title/status and retry with a backoff. General offers Retry saving and Open settings folder. Closing attempts a final save and offers retry, close without saving or Cancel on failure.
- One bounded FHP1 `host-preferences.dat` transaction holds the related host options, presentation, experience and chat/sound preferences. Its previous valid copy is backed up before atomic replacement. Startup reads the new store, recovers its backup if needed, or migrates the earlier separate stores; the old stores remain untouched. The earlier chat store's own backup is also recoverable. An invalid new store is retained separately during repair. No transcripts, drafts, Inventory contents or credentials are added to saved choices.
- Storage remains `%LOCALAPPDATA%\FolderstormSessions\Prototype-v1`, independent of install path and protocol version. This includes existing Character1–5 private profiles and custom WAV assets. Installing into another directory does not create a new host-settings namespace. Installing an older build that predates FHP1 cannot read choices first saved in the new store; its older stores remain available.
- The first-open marker writes its complete five-byte value and recognizes the four-byte markers produced by earlier hosts. Copy/Keep suppress subsequent setup prompts after successful process launch. Cancel/failed launch leaves setup available. Copy from main profile remains available later for a closed destination.
- Copy groups now include reviewed movement/WASD/quick-jump, camera/view, avatar/beams/LookAt, RLVa and account UI controls, alongside graphics, interface/skin, colors, bindings, quick preferences and toolbars. Groups are independent; native persistence/backup eligibility and type/value checks still apply. Exact behavior controls are reviewed; unrelated settings do not become eligible by sharing a prefix.
- Recognized packaged Firestorm/Modern/Phoenix/Hybrid/V3/Text presets supply source defaults omitted from `settings.xml`; remaining omitted eligible preferences use this viewer version's defaults. Source preset filenames are never adopted as arbitrary paths. Security/automatic-action choices, credentials, live restrictions, account contents, AO/Inventory/gesture data, contact/group lists, search filters and selections remain excluded. Custom asset references such as beam filenames are settings, not a general asset migration.
- The selected source account's UI preference snapshot is held before login and applied once after the first successful login establishes its destination account. DebugLookAt/HideOwn, crouch behavior and reviewed conversation/inbox/nav UI controls are supported. The destination's own controls/files are backed up, verified and rolled back on failure; no other account directory is overwritten. Failed authentication can precede success; detaching discards pending snapshots.
- Host settings use one themed category-navigation window: General, Appearance, Characters & profiles, Chats & notifications, Audio, Switching & monitors, Keyboard shortcuts and Quick actions. Existing menus open the corresponding category. Apply validates the whole draft, applies and saves; Cancel discards it. Dynamic profile selectors retain each profile's draft while switching and guard live account ownership. WAV files are created only after accepted validation. Fields resize within available width, long pages scroll, and navigation/footer remain fixed. Midnight, Daylight and Windows High Contrast behavior use the shared theme/font/DPI handling.
- Copy summaries distinguish copied preferences/files from unselected, isolated, unsupported or invalid entries. A bounded private `settings-import-report.txt` retains summaries and sample skipped control names, never control values. Characters & profiles can open it. Host status accepts later account/toolbar summaries rather than suppressing everything after the first report.
