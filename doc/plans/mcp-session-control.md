# MCP session controller and monitor tools

E9, depends on E0 and extraction of typed controller commands from tools/session-host/main.cpp. This is a separate authority surface from each character's viewer MCP connection. No credentials, automatic login completion, navigation or building.

## Controller-owned transport

Worker APIs cannot safely control logout/restart or unlaunched profiles: the connection disappears, and account credentials must not become global host authority. Add a current-user-only, authenticated controller endpoint with its own discovery namespace, random controller-instance epoch and independently managed opt-in permissions. Reuse proven discovery/ACL patterns, bounded local framing/HTTP and loopback-only scope; do not expose worker pipe secrets, arbitrary executable/profile paths, process handles or window messages.

Bind every command to controller_instance and stable profile ID/revision. Running-character changes additionally require expected worker identity/generation and exact viewer_session. Slot order, names, active selection and PIDs are display hints only. Stopped profiles have no login reference and use their profile identity/revision; do not fabricate one. Controller access cannot silently enable worker MCP or unpause denied account permissions.

Authorize in the controller and marshal typed commands onto its UI thread. Host responses never leak bearer tokens, password data or account-private Chat through session metadata. No generic host UI automation. The host accepts only its configured matching viewer binary and existing profile lease/state machine.

## Tools and choices

- `sessions_list/status`: configured profiles permitted by controller access, actual logged-in identity when permitted, active/background/disconnected/restart state, existing resource diagnostics. Opt-in metadata permission. Diagnostic freshness and unavailable fields are explicit.
- `session_activate`: explicit targeted handoff, reusing native serialization, input/microphone ownership and optional visual transition policy. Separate Ask-capable activation permission; never run as a side effect of reads, sends or monitor operations.
- `session_background_mode`: explicitly set Warm/Economy on an eligible inactive worker. No hidden promotion or ownership change; return Busy/RequiresInactive where appropriate. Ask-capable mode permission.
- `monitor_open/close/list`, `monitors_open_all/arrange`, `monitor_cycle_configure/pause/next`: reuse existing read-only low-resolution monitors, shared streams and render budget. Changes affect previews only, never avatar selection or active character. Preserve source-bound monitor Chat and pause-before-chat rules, stale-image clearing and DPI minimum-size validation. Ask-capable monitor-layout permission. No raising preview quality/FPS beyond configured bounds.
- `session_restart`, `session_logout`, `session_detach`: independent explicit lifecycle operations with separate Ask-capable permissions and action summaries. Restart is native close → release profile lease → open login window. Native logout cancellation, dialogs, delays and uncertain acknowledgments remain authoritative; no force termination, uncertain retry or automatic replay of messages. Detach is not logout and cancels pending relaunches. A disconnected profile may relaunch only through its current controller-owned recovery state.
- If launch is included, `session_open_login` opens the configured profile's native login window. It does not accept passwords, fill credentials, approve login, bypass duplicate-account reservation or enable Local Assistant. Native host approval must work even when no worker is connected.

Controller permissions and approvals are host-owned, not self-authorized by a worker/account. A worker's existing grant does not authorize control of other characters. New controller capabilities must be explicitly enabled. Store host choices with existing stable autosave/profile naming rules and native Apply/Cancel; do not write private viewer settings files.

## Transactions and safety

Lifecycle operations return controller-owned receipts with source profile/worker generation, phases and known/uncertain outcomes. Keep the receipt after the old viewer exits. If the host instance changes, reject the old receipt/capability; do not turn a retry into a new restart. One lifecycle owner per profile and one active-character handoff owner.

Reuse current handoff/modal/closing guards, restart cancellation, profile leases and mismatched-binary refusal. Pause-all revokes pending account work before any new side effect, but resuming an account remains an explicit native action outside MCP unless separately reviewed. Losing the controller releases ownership through existing recovery; no orphan input/microphone owner. Do not automatically restart on a disconnect event.

## E9 implementation checkpoint

The host now owns a separate current-user-only Windows named pipe. Discovery is under the Windows Local AppData known folder, `Folderstorm/controllers/controller-<instance>.json`; the file and pipe have a protected current-user ACL. Its 256-bit secret remains inside discovery/client transport and never appears in a tool result. The Go client also checks discovery-file ownership/ACL and the pipe server's user before sending the secret. There are no URLs, executable paths, credentials or HWNDs in tool arguments. Other operating systems report unavailable.

Native Preferences has a separate **MCP controller** category: access defaults Off, metadata defaults Never, each write class defaults Ask, and all five saved profiles default opted out. Explicit Apply/OK accepts the draft; Cancel leaves controller choices unchanged. `host-controller.dat` retains random stable profile IDs and policy/profile revisions through normal host saves. Viewer Local Assistant settings and grants remain separate.

The fixed tool surface is `controller_list`, `sessions_list`, `session_status`, `controller_operation_status`, `session_activate`, `session_background_mode`, `session_open_login`, `session_restart`, `session_logout`, `session_detach`, `monitor_list`, `monitor_open`, `monitor_close`, `monitors_open_all`, `monitors_arrange`, `monitor_cycle_configure`, `monitor_cycle_pause`, and `monitor_cycle_next`. Every call except discovery requires an explicit controller instance. Running writes also require exact profile revision, worker ID/generation and opaque viewer session; stopped-profile login requires its profile ID/revision. Worker login references are available to the private host pipe while worker MCP is disabled, without enabling it or publishing a simulator session UUID. A pre-login worker has no ready login reference and is reported unavailable for running controls.

Mutations return a pending receipt before native approval. Approval describes frozen profiles/accounts and action parameters; source/policy checks run after approval, at worker-pipe submission, and before restart relaunch/CreateProcess. Native restart cancellation, matching binary, leases and handoff recovery remain authoritative. A detach approval may supersede an armed restart; it holds only the relaunch while approval is pending and cancels it on acceptance. If native close was already submitted, receipts report that uncertainty. Lifecycle receipts outlive worker exit. No uncertain operation automatically retries or forces process termination.

`controller_list` supplies a timestamped random request ID for one intended mutation. IDs admit for 60 seconds with 5 seconds future-clock tolerance. The host retains up to 128 receipts for at least 10 minutes and refuses capacity instead of dropping active work. Reusing an ID with changed material arguments conflicts; an expired evicted ID cannot become a fresh mutation. Poll the original ID after an uncertain response. Ask/operation authority expires after 70 seconds using the monotonic host clock. The admission high-water mark advances by elapsed monotonic time even across idle periods, before timestamp validation and receipt eviction; wall-clock rollback therefore cannot revive expired request IDs. Pipe requests are fixed 4,096-byte bounded frames, responses at most 65,532 JSON bytes, and connected I/O expires after 3 seconds. Reads return cached snapshot age and unavailable diagnostic fields explicitly.

Monitor tools preserve four fixed previews plus the separate cycling preview, native aggregate render budgets, configured quality/rate and source-bound Chat. They return metadata, never images or Chat. Window/source/order/screen snapshots invalidate stale approvals; arrangement checks all DPI minima before moving anything. Open-all refuses fixed-monitor capacity conflicts before opening windows. Cycling uses frozen opted-in sources; Next freezes its exact selected source, and manual cycling supersedes controller ownership. No monitor operation activates a character.

Integration hook: call exported `mcptools.RegisterController(server)` once in `NewMCPServer`. Controller implementation files do not modify the central viewer registry or worker IPC version. Add portable CMake checks `controller_mcp` and `controller_dispatch` using their corresponding `tools/session-host/tests/test_*.cpp` files; existing include directories suffice.

Focused validation covers the production portable host dispatch adapter, permission/source changes during Ask, transport revocation, changed monitor bindings/layout, restart authority after expected process exit, detach cancellation of relaunch, independent Go discovery/client/tool binding, secret redaction and Windows Go adapter compilation. These are not native viewer/host builds or Windows acceptance. Independent Max review and native Windows acceptance remain required before completion.
