# Guarded native creation and appearance operations

Follow-up above #44. Three stacked checkpoints; preserve history, do not merge.

1. Durable, viewer-owned execution authority survives the HTTP response. It binds actual login/account/grid/bridge generation, permission revocation and deadline; cancellation is latched. Bounded receipts distinguish pending, submitted, partially submitted and cancelled-before-submission outcomes. No uncertain replay or automatic rollback. Existing managed exclusions remain at this checkpoint.
2. Propagate authority through native item creation, including template copies, permission/content follow-ups, wearables, environments and landmarks. Assistant creation must not activate gestures or open editors. Restore managed createItem only after its supported paths are covered.
3. Propagate the same authority through outfit/item wear and detach, inventory/library fetch/copy, COF updates, wearable loading, attachment confirmations, deferred callbacks and destructor callbacks. Preserve ordinary native/manual behavior and all native restrictions. Restore managed appearance writes only after the whole chain is covered.

Use operation-scoped context and captured callback leases; never leave a sticky global guard on unrelated viewer work. Check ownership, deadline, permissions and native restrictions before further side effects. Already submitted simulator changes may complete; continue ordinary native reconciliation, retain known result IDs, and report uncertainty. Bound work, receipt retention and callback bookkeeping. Apply/Cancel, existing policies, microphone/input ownership and background render modes stay intact. No host pipe protocol change is expected.

Focused checks: delayed callback pause/revoke/re-enable, ownership changes and detach, duplicate deliveries, expired work, destructor/deferred work, partial submission and independent concurrent operations. Native Windows acceptance: each supported item type and template path; own/library outfits; append/replace; attachment and wearable restrictions; Warm/Economy, two/five characters, ordinary viewer regression and no unexpected UI/focus. No broad/native builds, packaging, GitHub builds or unrelated tests during implementation. Senior review follows the completed stack.

Checkpoint 1 actual checks: strict portable C++17 durable-lifetime/latched-cancellation/scope-restoration/duplicate-delivery tests passed. Affected Go MCP-tool tests passed, including tool schema coverage for the new source-bound assistant_operation_status tool. Diff hygiene passed. Native compilation/runtime remains pending.

Checkpoint 2: guarded inventory callbacks retain operation scope through normal and AIS delivery, drain failure callbacks under stopped authority and suppress duplicates. Item/template copies and follow-up permission writes check authority immediately before network submission. Permission defaults and template selection are frozen/validated at preparation; custom script copying also requires Move/Copy permission. Assistant-created gestures do not activate or open editors. Wearable upload callbacks retain scope; environment callbacks drain safely; landmarks receive a tracking callback. Native callbacks retain ordinary behavior outside an assistant scope. Managed createItem is restored; managed appearance remains refused until checkpoint 3.

Actual checks: strict portable guard/dispatch/session tests pass, including delayed creation → pause → no permission writes, duplicate callback delivery, cleanup and known-result retention. Native compilation and each native item-type/template acceptance case remain pending.

Checkpoint 3: appearance callbacks/destructors, category fetch/copy, wearable holding patterns, attachment queues and late attachment COF links retain their originating guard. Each queued attachment keeps bounded provenance, including stopped tombstones, so a late arrival cannot turn into unguarded link work. Manual appearance intent supersedes unfinished assistant work. Native restrictions are checked again during callbacks and before queued attachment submission. Snapshot source scope is frozen; library copies require Create and Move/Copy as well as Wear. Owned outfits use the normal no-copy native path. Cold outfits trigger only a read fetch and an explicit no-changes loading response; saved outfits are bounded at64folders/256items and individual requests at50items. No automatic mutation replay.

Bake coroutines carry explicit authority, rather than holding thread-local context across a suspension; assistant bake requests are not retried on uncertain failures. Native/manual behavior remains unguarded outside a captured assistant scope. Managed appearance is restored and capabilities updated. Windows native acceptance remains pending; portable helpers do not compile or exercise the full native callback graph.

Senior review revisions: restriction checks are lifetime-independent; Allow dispatch retains native confirmation. AIS commands capture authority at enqueue, recheck immediately before transport and restore it only for callback delivery. Same-login responses reconcile normally; explicit login checks abort old inventory responses even after reconciliation yields. Prequeue checks do not count as submitted network writes. Cancelled creation replies retain their operation ID and known results. Attachment callbacks are allocated only for their actual source; expired deferred observers drain pending-link bookkeeping. New unsent intents replace stopped queue entries; ambiguous in-flight duplicates refuse instead of replaying. Missing/corrupt or duplicate wearable asset recovery requires the native viewer rather than silently creating/editing assets under Wear permission. Holding-pattern cleanup uses a single lifetime-safe drain after timeouts and cancellation.

Published draft checkpoints: [#45](https://github.com/DrCum/Folderstorm/pull/45) durable guards/receipts, [#46](https://github.com/DrCum/Folderstorm/pull/46) guarded creation, [#47](https://github.com/DrCum/Folderstorm/pull/47) guarded appearance. Build in order with matching viewer/host/sidecar. No host protocol increment beyond16.

Native acceptance additions: queue AIS work, pause/revoke before transport, then resume and verify no cancelled request submits; pause during bake suspension and verify a later native bake is not suppressed; cancel delayed COF-link observers and verify pending links drain; issue two same-item wear intents before idle drain; exercise corrupt/missing and duplicate wearable assets without fallback creation; change login during an AIS response/model yield and verify no old result reaches new inventory. Query receipts after creation cancellation and inspect known IDs/partial state. There is no automatic retry or rollback of uncertain writes.
