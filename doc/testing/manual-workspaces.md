# Manual workspace acceptance

The manual Workspaces feature lives under Preferences > Move & View > Workspaces. Account-local named arrangements are committed by explicit Preferences OK. Automatic restore at login, imports, arbitrary windows, conversation sessions, and inventory contents are outside this release.

Automated validation covers strict LLSD parsing/serialization, profile limits and UI-unit fitting. Runtime source files have been syntax-checked against the viewer's actual headers/dependencies. The following native viewer checks still require a logged-in viewer and are not claimed as completed by those checks.

1. Before login, the selector and editing buttons must be disabled. Log in; arrange primary Inventory, Mini-map and World Map. Save current under a new name. Cancel should discard the name; saving again and pressing OK should retain it when Preferences reopen and after restarting the same account. A different account must have a separate collection.
2. Save A and B with different rectangles, visibility and minimization. Preview A, then B, then Cancel/close Preferences. Original live arrangement and ordinary per-account rect/position/visibility controls must return. Explicit OK should retain B. Reopening a utility window must use the retained/restored placement. Generic Preferences construction/open must never accept a pending definition.
3. Rename and delete custom arrangements. Builtin starting arrangements are not editable saved records. Cancel discards the operations; OK retains them. Leave an overwrite/delete prompt open, start a new preview or close/reopen Preferences, then answer the old prompt: it must make no change.
4. With Received Items available, save two primary pane sizes/collapse states. Preview and Cancel must restore the live split and its saved controls. Repeat with a primary opened manually after Preferences. In a developer fixture, use a valid pane-only workspace with no Inventory window record: Cancel must still restore the pane. Without Received Items available, preview must skip adjustment without enabling or fetching it.
5. Open a manual additional Inventory window. Preview Inventory sorting repeatedly: exactly one distinct workspace-owned extra should exist, manual extras stay untouched, and primary placement should reopen correctly despite group cascading. Cancel should remove/hide the feature-created extra. Focus the owned extra and verify Share, active selection, and single-folder routing target that window. Exercise ordinary logout/quit content cleanup.
6. Open Inventory Filters before Preview Driving or another geometry restore. Its parent must be skipped with an explanation; Filters and parent arrangement remain intact. Separately preview a parent that initially has no Filters, then open Filters manually and Cancel: parent state returns without moving/closing that new Filters window. A new owned extra with a new dependent is retained hidden as the single reusable extra so Cancel preserves that manual window; the next sorting preview must reuse it.
7. Test standalone Nearby Chat visible and hidden, including Driving then Cancel. Console session housekeeping and input draft must match the restored visibility. Test hosted Nearby Chat: workspace preview must not tear off a tab, change selected conversations, host visibility, chat presentation settings, transcripts or session count. Receive an IM during preview and Cancel; that session stays intact. Existing conversations host geometry may restore without opening or hiding it; minimized/absent hosts are skipped.
8. While an idle placement is pending, Cancel, start another preview, log out, or switch accounts. No earlier continuation may move/open a utility for the later transaction/account. Preferences focus must survive utility opening.
9. Resize to a narrow/tiny client and test changed UI scale/DPI, removed monitor, nonzero floater-frame origin, and both skins. Windows retain actual minima; oversized minima keep the right-hand close control and top title edge reachable. Adjustments are reported and do not silently overwrite the named definition.
10. Under RLVa ShowInv restrictions, the owned extra must be filtered/closed like other Inventory windows. Preview and rollback must honor current visibility restrictions. Driving and Inventory sorting must preserve viewport/chrome/Mouselook and must not change the camera, vehicle controls, folder/item selections, filters, permissions or inventory contents.

Build each supported viewer backend and run the existing viewport/profile and assistant checks with the combined implementation. A native Windows/macOS/Linux pass remains distinct from the headless geometry/serialization and source checks.
